# Experimental Atelier contract, v1

Local Node HTTP server plus framework-free browser. Domain module `scripts/atelier/domain.mjs` uses only JavaScript, no file/network/process APIs, and exports the functions below. Server owns JSON persistence and revision concurrency. UI never interprets strings as HTML/code. Inputs are fictional workflow prototypes; this finite-state boundary cannot model arbitrary software.

Project schema: `{format:1,id,title,brief,actors:[{id,label}],constraints:[{id,text}],sources:[{title,url,note}],questions:[string],records:[{id,title,state,owner}],variants:[{id,title,premise,tradeoff,design:{layout:'board'|'list',accent:string},architecture:{boundaries:[string],data:string,tradeoffs:[string]},states:[{id,label}],actions:[{id,label,kind:'create'|'transition',from:[stateId],to:stateId,actors:[actorId],otherOwner:boolean}]} `. IDs are bounded safe slugs; user strings are bounded; 2–4 variants, 1–8 actors, 1–12 states per variant, <=16 actions, <=200 records. `otherOwner` prevents the record owner performing this action. Variant state IDs must admit the project's starting records. No executable expressions or generated HTML. Unknown malformed data fails clearly; no silent repair.

`validateProject(project)` returns a cloned validated project or throws a readable Error. `createSession(project)` returns `{format:1,revision:1,project,lanes:{[variantId]:{records,events:[]}},situation:[],decision:null,history:[],requests:[]}`. Actual record titles/owners/IDs survive transitions.

`performAction(session,input)` is immutable and returns `{session,outcomes}`. Input `{variantId?:string, actionId, actorId, recordId, title?:string}`. Without variantId, apply exactly the same intent independently to all lanes and append it to situation. A create action uses the caller-supplied common recordId, actor as owner and trimmed 1–140-character title. Refused transitions return allowed:false and a clear reason without changing records; all lane observations include action, actor, record, before/after state and reason. Unknown actor/action/record, duplicate create, wrong source state or otherOwner violation never fabricate success. Other lanes cannot affect the outcome. Events carry no invented wall time.

`replaySituation(session,steps=session.situation)` starts from project.records for each variant and replays ordered shared inputs, preserving context/decisions/history. `chooseDirection(session,{variantId,reason})` records chosen variant snapshot, project revision, scenario and reason, retaining prior decisions in history. Reason must be nonblank; choosing does not certify quality. `reviseIntent(session,{brief,constraints})` updates context, increments project revision and marks existing decision reviewNeeded; preserves every lane record/event and old decision reason. This is declared reconsideration, not semantic dependency inference.

`applyProposal(session,{baseRevision,summary,variants})` rejects stale baseRevision, validates 1–4 incoming variant definitions merged by ID into current project, increments revision, preserves existing lane records/events and old choice/reason, marks reviewNeeded. Every current record state and owner must remain valid in its updated variant, otherwise reject with explicit migration-needed error; do not drop or rewrite records. New variants start with project.records. No variant removal in v1. Proposal import is a real external agent/file boundary, not a mock LLM. Source/brief edits remain separate user actions. `exportDecision(session)` returns JSON containing context, chosen variant, full decision/history, scenario and actual lane observations, with explicit research-prototype/non-production label.

Each new decision additionally snapshots `context:{brief,constraints,sources,questions}` and `observations:lanes`. Thus direct trials and original intent survive a later replay or revised need. Existing decisions from before this experimental addition are retained without inventing missing observations. Replaying replaces live trials; the UI confirms when individual trials would be lost and leaves decision snapshots intact. Review-needed reflects changed project intent/definitions, not a false certificate that latest trials equal a historical choice.

All mutations are copy-on-success; rejected input leaves the original session unchanged. Server adds a separate storageVersion optimistic lock for concurrent browser tabs. Persistence uses atomic rename before acknowledging success. Local listening is loopback only with same-origin mutation checks, bounded bodies and explicit content types. No arbitrary shell/provider execution. Prototype export returns data plus an agent-ready task; no claim of production deployment or arbitrary-project understanding.
