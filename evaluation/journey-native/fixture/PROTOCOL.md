# Repair Café two-session smoke protocol

Authored 2026-09-16 before native calls. One complete, deliberately small CLI product and one compatibility change. It is an authored smoke task, not a held-out product population or user study. No visual UI is requested; this task cannot validate the visual workflow.

All three conditions receive the same initial brief and complete independent ordinary acceptance checks. No arm gets weakened tests. Candidate input binding is app.mjs. HANDOFF.md is an additional required artifact assessed for usefulness by the coordinator; its mere existence is not semantic proof.

The operator keeps maintenance requirements/checks outside each initial workspace. Before session two, prepare-maintenance.mjs creates saved-jobs.json through the initial implementation; any failure is retained and a clearly labelled canonical fixture is substituted, never counted as successful end-to-end continuity. Then overlay the maintenance files. External evaluation after session two also checks preserved operator data separately. Every acceptance operation runs a new real Node process, so object re-creation is not substituted for restart.

Ordinary test command in each workspace: `node acceptance.mjs .`. External command: `node /tmp/devmethod-native-task-fixture/evaluate.mjs CANDIDATE initial|maintenance`. Lab adapters are in evaluator/, with separate stage contracts. Calibrated controls test the same public requirements. Each adapter emits protocol-valid JSON even for behavioral failure and exits zero, so infrastructure failures remain distinct. Do not expose controls as requirements or change them after observing native results.

Fixture calibration is deterministic only. It establishes that supplied tests accept the reference and reject named seeded faults; it does not establish complete requirement coverage, model behavior or semantic independence of a model's self-written tests. The reference supports the optional category already, but it is never provided as implementation input.

Native admission/model/limits/order are owned by the separate driver. At most six calls: one initial and one maintenance session per A/B/C. Fresh isolated workspaces, same model/settings and available ordinary tools. Candidate C may use the optional lab; do not force overhead absent task need. Stop under the admitted token/time rules. Report success, failures, interruptions, unknown metrics and setup assistance separately. A single observation per condition establishes no general comparative advantage.

Freeze all fixture bytes and calibration observations in SHA256SUMS before native dispatch. Preserve this exact population and results; later corrections require another identified protocol version. No product fixture or native candidate is edited by the evaluator except temporary state files; maintenance setup is explicit operator assistance.
