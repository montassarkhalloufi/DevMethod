# Scenario provenance and current comparator boundary

Consulted 2026-09-16. Reuse the [dated community-source audit](../../HARDENING-0.5-SOURCES.md); its anecdotes motivate scenarios, not claims about present products. Reports of obsolete instructions motivate changed-rule reconciliation; preference for smaller diffs motivates a local repair; long-running harness reports motivate interruption/handoff inspection. These capabilities are already written in DevMethod. This tranche measures their execution rather than adding another rule.

Primary release pages were opened afresh before comparison statements:

- [Spec Kit v1.0.7](https://github.com/github/spec-kit/releases/tag/v1.0.7), published 2026-09-15, release commit displayed `fe1d00e`. Its current documented entry points include feature work, bug fixing and idea assessment. It is not treated as mandatory full specification for every small change.
- [BMAD v6.12.0](https://github.com/bmad-code-org/BMAD-METHOD/releases/tag/v6.12.0), published 2026-09-04, commit displayed `05bfbd4`. Release notes explicitly address proportionate small-change flow, evidence-bearing review triage and reuse of settled review outcomes.

Neither method is executed in this bounded A/B tranche; no superiority over either is measured. The comparator is the same native agent with reasonable ordinary instructions, versus stable DevMethod. The old testimony cannot establish a current competitor gap.

For host behavior, [OpenAI's non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode) and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) were opened alongside the installed CLI's pinned behavior. Historical usage recovery and shell restrictions are based on local traces/probes, not on assumed current documentation. No API key or new provider is introduced.
