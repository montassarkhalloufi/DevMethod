## Predictions and limits fixed in advance

1. The candidate can show different actual permission/state consequences for identical actions in independently authored finite-state projects without code changes. It loses this claim if the new context requires information, relationships or interaction it cannot represent. A partial mapping must name the omitted need.
2. A user can keep a reason and original observations, change the need, import a compatible real agent proposal and exercise it without losing records. Passing tests or automatic `reviewNeeded` alone do not establish this.
3. Shared replay reduces repeated manipulation when inspecting the same sequence across variants. This is a mechanical claim, **not** a claim of improved judgment, human time saved or product novelty. An ordinary script can also replay; it remains available to the simple condition.
4. If ordinary prototypes plus conversation preserve the relevant intention and produce an equally usable change with less work, prefer that approach. If the benefit exists only in the bespoke Gazette data, reject generality. If the bounded model cannot express the important issue, reassess the transaction/dependency conceptions before adding more simulation knobs.

**Strong simple comparator:** an ordinary capable agent, the same brief/facts/accepted constraints, ordinary design/research/files/tools, permission to ask questions, create multiple prototypes or a small script, and a short decision note.
