# Observations and decisions — maintenance value

Later interpretation note: the owner clarified that DevMethod should amplify human work through guidance and context management. This frozen protocol supplied resumption notes, compatibility decisions and verification rules before implementation; it did not evaluate constructing them with a person. Its stopped/not-run outcomes below remain unchanged. See the [current measurement objective](../product-alternatives/EMPOWERMENT.md).

No relative benefit of DevMethod has been measured in this tranche. The tiny native admission failed before a model event; the predeclared stop prevented all six A/B slots. The delivered corrections improve the evaluation instrument's local execution and evidence preservation. They are not a demonstrated improvement in an agent's maintenance work.

The evaluator's healthy and faulty reference implementations establish that its checks distinguish their intended cases. They do **not** establish that an agent discovers those faults, writes equivalent tests, or follows the method. The baseline intentionally has good instructions, including preservation of unrelated work. Instruction overlap prevents attributing a hypothetical result to one repeated sentence.

The [public fixture artifact](../../../evaluation/maintenance-fixtures/README.md) retains 21 V3 calibration cells: three starting implementations, three healthy references and 15 targeted mutations. It also preserves V1's syntax failure and V2's three interrupted cells; the corrected V3 classifies all 21 as expected. Reproduction of these fixed verdicts is deterministic checker validation, not 21 successful maintenance tasks. Each V2/V3 calibration uses 21 outer evaluators and 30 store-probe processes. No lab runtime is required.

Exporting without nested `.git` directories exposed a separate adoption defect: the historical setup recreated a different HEAD even when files, index, diff and status matched. The small companion restores bounded Git bundles and verifies those properties. Five public adoption checks pass (three exact restorations and two expected refusals). The public resume baseline deliberately has a derived HEAD because one executable path was anonymized; its original diff/status are preserved exactly. Original/private and derived/public identities are explicitly separated. This is measured local reproducibility, not agent resumption benefit or universal cross-platform portability.

## Execution and accounting

The [native evidence](../../../evaluation/maintenance-native/README.md) records one admission, zero completed turns, exit 1, 0.04 seconds, no final response, no commands, no worker changes, and unknown input/output/cache tokens and monetary cost. The six comparison slots remain not-run. Manual intervention count and operator productivity were not measured; coordinator preparation, fixture corrections and diagnostic work must not be treated as autonomous worker success or free overhead.

No agent-authored tests exist to challenge. Their sensitivity, false-success claims, regressions and repeated work are unavailable, rather than scored zero. No browser result exists; the evaluator's DOM/VM checks are not visual evidence. The reserved new product context remains unused because no A/B gap justified a candidate C. No transfer or general superiority claim follows.

[The local startup diagnosis](../../research/maintenance-startup-diagnosis-2026-09-16.md) reproduces the EPERM before typed configuration validation. A metadata exception for exactly the two worker ancestors removes that barrier while protected reads and listings remain denied. A fresh-tree regression and a deliberately invalid configuration probe verify this bounded repair without a model. They do not prove later startup/inference succeeds, and do not clear the stopped campaign.

## Adopted, simplified, abandoned, indeterminate

| Track | Decision | Reason and boundary |
| --- | --- | --- |
| Ordinary strong tests for the previous restart cases | Adopted | Retain the earlier equal detection result with fewer checker invocations. Do not rerun the old campaign or promote its lab to a default |
| Task-local zsh temporary prefix | Adopted for the optional native instrument | Actual sandbox heredoc failed before and passed after setting TMPPREFIX alongside TMPDIR. Scope remains local shell execution |
| Shell-visible Node selection | Adopted for the optional native instrument | The login shell selected Node 23 despite a Node 24 parent. Non-login configuration plus pinned PATH and an actual runtime probe establishes the intended local runtime |
| Worker path resolution under the outer sandbox | Adopted for the optional native instrument | Permit only ancestor metadata, retaining protected content/metadata and listing denials. Prefer this to broadly allowing all protected metadata. Local startup validation succeeds in a new tree; native completion remains unverified |
| Pre-admission evidence protection | Adopted | Three red-to-green regressions cover nonterminal commentary, known usage surviving a raw-output collision, and changed Git staging with identical working bytes |
| Reproducible case adoption after packaging | Adopted for this experimental artifact | Bounded bundles preserve the declared initial Git state; a 5/5 local adoption check verifies the public derivative. A generic repository-restoration engine would exceed this need |
| Extra method rule or mandatory maintenance stage | Abandoned for this tranche | Existing procedures already cover the three needs; no observed behavior justifies duplicating them |
| Generic new maintenance engine / broad lab expansion | Simplified to ordinary fixtures and existing assertions | A frozen case evaluator and an opt-in host driver suffice for the proposed experiment. Neither becomes a distributed mandatory workflow |
