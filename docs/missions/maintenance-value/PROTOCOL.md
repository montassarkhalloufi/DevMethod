# Frozen comparison design — before native dispatch

## Question and falsifiers

Does stable DevMethod help a coding agent preserve valid decisions/evidence and unrelated work, implement a changed rule without damaging old data, and choose proportionate verification for a small repair? Ordinary good instructions are the baseline. The product, architecture and visual direction remain the same within each pair. No lab is required or scored as success merely for being invoked.

A demonstrated result must separate functional acceptance, test construction, accurate handoff and unnecessary repetition. If ordinary work performs equally well with less observed work, prefer it for that situation. A candidate C is justified only by an observed, diagnosable gap; do not spend additional calls to obtain a desired ranking. One pair per case is exploratory, not statistical/general evidence.

## Reconciliation and admission

The prior A-initial call produced a functional product and passed checks but reached the 120-second supervisor limit before final handoff/usage. It is not automatically a product failure. Its `--ephemeral` session has no recoverable completed-turn usage in inspected local traces. Preserve the immutable old result; unknown tokens are not zero. A shell heredoc encountered an unrelated temporary-path restriction: TMPDIR alone does not relocate zsh TMPPREFIX. Correct and probe the actual shell path before spending another call.

The user's new request expressly authorizes diagnosis, a tiny complete trial and then a bounded comparison, including disclosure of unavailable consumption. This is a newly frozen task/protocol under that instruction, not resumption/reset of the stopped Repair Café campaign. No billing reconciliation or remote cancellation is claimed. No purchase, quota reset, alternative credential or API fallback.

One readiness slot must finish a tiny clamp repair, produce a final response, expose valid token usage and pass independent checks before comparison starts. Failure, timeout, unknown usage or missing completion stops admission. Preserve every admitted slot and all later not-run slots. The parent must not rerun the same slot.

## Pinned controls and limits

- Codex CLI 0.147.0, authenticated existing ChatGPT subscription; model `gpt-5.6-sol`, reasoning `low`. Freeze actual Node executable/version, PATH resolution and driver hashes.
- At most **7 calls**: readiness plus six A/B slots; **120 seconds** per call, 1.5-second termination grace, 2 MiB combined output, one active call. Stop between calls at **100,000 observed input+output tokens**. This is not a hard token/dollar cap; a call may cross it. Cash cost is unavailable. A timed-out/unmetered call stops the series even if its product passes.
- Freeze all three cases, acceptance criteria, initial states and withheld controls before readiness; no independent check is given to a producer. No agent nested workers, plugins, hooks, connectors, browser or network tools. Ordinary local read/edit/command tools are identical within each pair. Global skills are disabled through the same path overrides; B alone receives stable DevMethod at `6f31552` and its optional offline CLI. Project-specific policy/profile and scenario instructions are identical.
- A uses a strong ordinary instruction; B is told to use the installed method proportionately. This compares available method+instruction, not an attribution to any single sentence or mechanism. All six DevMethod capabilities remain available; no creative stage is removed to improve a score.
- Order: A/B on case 1, B/A on case 2, A/B on case 3. One repetition; no automatic retries. Separate Git working directories preserve each case's real partial/unrelated diffs. Do not commit those diffs during preparation.
- An outer macOS read-denial profile blocks evaluator/original fixture, parent source checkout and sibling worker contents. Actual negative read probes must pass before admission; producer commands retain the host's workspace-write restrictions. This is an inspected local isolation profile, not a universal hostile-code sandbox.

## Independent evaluation and measures

The evaluator author owns case requirements, hidden checks, healthy controls and targeted faulty variants. Freeze their byte hashes and calibrate intended pass/fail outcomes before native dispatch. Unexpected imports/process failures are unavailable verification, never semantic fault detection. Agent-authored tests are preserved separately; challenge them after execution against undisclosed plausible faults, without giving those faults or expected outputs to the producer.

Report for each slot: admitted/completed/interrupted state; independent criterion outcomes; changed and protected paths relative to the actual starting bytes; generated tests and their sensitivity; claims unsupported by checks; repeated commands versus retained unchanged evidence; recorded agent interventions; wall time; provided input/output/cache tokens; cash cost unknown. Operator setup/review time is separate and not a measured human productivity effect. Cached input is reported within input, never added twice. Runtime/model/provider variability remains a confound with one repetition.

Manual review assesses correct ownership/attribution, relevant decisions, handoff accuracy, architecture boundaries and UI coherence where affected. Real browser inspection is separately labeled; a DOM/mock assertion is not visual fidelity evidence. No new visual direction is requested. New-context transfer is reserved before candidate design; if no candidate is justified or budget stops, mark it unexecuted and make no transfer/generalization claim.

The executable frozen JSON and raw transcripts identify actual dispatched prompts, hashes, order and outcome. Later corrections to the protocol cannot retroactively validate earlier runs. No source revision or fixture may be silently updated after admission.
