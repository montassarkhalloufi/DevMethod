- **Present and verified:** a named deterministic mechanism was exercised; only that layer is verified.
- **Partially verified:** implemented, but one or more relevant execution layers remain missing.
- **Instruction only:** guidance exists, without enforcement or measured compliance.
- **Limited experiment:** a pinned historical or current bounded observation; no general transfer.
- **Missing:** no implementation for the named capability; this need not justify adding one.
- **Not applicable:** a proposed addition does not resolve an observed need in this candidate.
- **Unknown:** evidence or access is missing; no success or failure is inferred.

## Candidate evidence and review

The starting candidate passed 168 local tests in this session and exact starting-head Linux/macOS/Windows/fullstack CI. Corrections have independent review: science reviewed the loop against the fixed protocol and native admission against actual adapter return shapes; a different guidance reviewer reviewed evaluation changes. That review found an oracle false negative for legitimate design exploration and it was corrected before integration. The root writer owns documentation and final integration; maintainer review of the final candidate remains separate.

The [follow-up record](HARDENING-0.5-AUDIT.md) and draft PR hold current integrated tests, archive integrity and final-head workflow conclusions. Any later payload/source change invalidates the affected evidence and requires a regenerated archive. The release checklist governs exact-candidate maintainer review; a PR is not a merge and a merge is not registry publication.

The native campaign remains **36 not-run, zero native completions, null pass rate among completions**. Fixture tests, these research workers, source citations, and valid scorer exit codes cannot fill those slots. Historical six-run exec evidence and three-root app-server evidence remain separately qualified in [native results](NATIVE-PILOT-RESULTS.md) and [adapter results](CODEX-ADAPTER-VALIDATION.md).

The [semantic probe](../evaluation/hardening-audit/README.md) is a direct counterexample to treating `closure supported` as business certification. The existing [Work Mode review](../evaluation/work-mode-review/README.md) is one real defect-detection observation, with no matched model control. Lie groups, relativity, a context optimizer and general orchestration were not added because no superior mechanism or proportionate validation emerged for the observed defects.
